# 项目故事 / 面试话术

> 用途：面试自我介绍、简历展开、技术追问时的准备。

---

## 1. 一句话介绍

**我把"图片转成可编辑 CAD 矢量图"这件事，做成了一套多 Agent 协同系统：算法负责精确、大模型负责理解、用"渲染回图比对"做客观裁判。**

---

## 2. 痛点（为什么做）

- 制图行业里，把照片/草图/扫描件重新画成 CAD，是纯重复劳动，慢、贵、易错。
- 市面上的**光栅转矢量工具**（R2V、img2cad）只会描像素边界，输出一堆碎线，不懂什么是直线、圆、标注。
- 单纯让**大模型看图写代码**，坐标不精确，画出来"像但不对"。

**我的定位**：不追求全自动（业界没解决），做**辅助级**——AI 出 70~80% 初稿，人工精修。

---

## 3. 方案是怎么一步步演进的（这段最能体现思考）

1. **先做确定性 CV 矢量化**（OpenCV + RANSAC）
   → 坐标精确，但输出一堆碎线，因为它分不清"几何"和"标注（尺寸线/中心线/剖面线）"。

2. **想到让大模型来帮忙**，于是设计多 Agent：
   识别 Agent（VLM+OCR）、提取 Agent、校验 Agent、Leader 决策回环。

3. **发现关键问题：校验必须客观**
   不能让 AI 自己说"我画对了"。所以我用「**把生成的 DXF 渲染回图片，和原图逐像素比对（SSIM/IoU/Chamfer）**」当裁判。这是整个项目的灵魂。

4. **做了 A/B/C/D/E 五臂对照实验**（详见实验记录）
   - 发现：**接地式代码生成（D）在 CV 可靠时最好；纯语义生成（B）在 CV 失效时更稳**。
   - 结论：**没有单一路线通吃** → 设计**多臂集成 + 客观仲裁**：跑多条路线，谁渲染出来最像就用谁。

5. **加"保最优"机制**
   大模型有随机性、调参可能变差。所以我让每一轮结果都和历史最优比，**最终输出永不差于基线**。

6. **算法持续增强**
   图框/标题栏剔除、多方向剖面线剔除、**圆周覆盖度验证**（去假圆）、尺寸线剔除。
   确定性通道 real04 从 0.38 → 0.53。

7. **加「图元装配层」**
   共线合并、角度吸附、端点吸附、**矩形装配**（4 条边 → 闭合多段线）。
   把"碎线"变成"结构化形状"（real01 从 6 个图元压到 3 个）。

8. **明确边界（诚实）**
   复杂多视图装配图仍是"部分重建"——瓶颈是**检测不全**，装配层只能规整已抓到的，
   补不回没抓到的。所以我把工具定位成：
   **简单/中等工程图（模式①）+ 假山/有机形状（模式②）**，复杂装配图列为已知局限。

9. **加上"大模型直接画"这一路（DS 臂）**
   对比了多种视觉模型后发现：**DeepSeek（`deepseek-chat`）具备视觉能力**，能看图直接写
   ezdxf 脚本。给它**正确的 API 用法 + 错误反馈重试**后，脚本成功率大幅提升，
   在 real02 上直接夺冠。于是把它作为独立一臂加入**集成仲裁**。
   → 平均最佳从 **0.729 提升到 0.756**，最难的 real04 从 **0.53 → 0.63**。

---

## 4. 技术难点 & 解法（面试官爱问）

| 难点 | 我的解法 |
|---|---|
| 大模型给不出精确坐标 | 让算法量坐标，大模型只写"组装脚本"（接地式生成） |
| AI 会幻觉、自评不可信 | 用渲染回图 + 像素指标做**客观裁判** |
| Agent 调参可能越调越差 | **保最优**：只留历史最优，保证不下于基线 |
| 不同图难度差异大，单路线翻车 | **多臂集成 + 仲裁**，自动选当轮最优 |
| 剖面线/尺寸线/图框是"非几何"干扰 | 专门的清洗算法（多方向检测、区域生长、OCR 邻域） |
| 假圆（椭圆被当圆） | 沿圆周采样算"墨迹覆盖度"，低于阈值判为假圆 |
| OpenCV 中文路径读写失败 | 封装 `imdecode/imencode + tofile` 兼容层 |

## 5. 数据与结论

- 合成数据集（自带精确标准答案）：IoU ≈ 1.0、SSIM ≈ 0.8
- 真实图集成流水线：**简单/中等图 SSIM 0.75~0.84，复杂装配图 0.53**
- 五臂对照：**E（集成仲裁）平均最优**，且数学上保证不下于当轮最优单臂

## 6. 假山 / 有机形状通道（第二条产品线）

**背景**：我的 AI+CAD 发明专利针对的是**园林假山**——不规则的自由曲线，和机械工程图完全不是一类问题。

**过程**：
1. 先拿卖家打包的开源项目 **Image2CAD** 试 → 它面向机械图，**假山上几乎提取不出东西**
2. 把 Image2CAD 从 **OpenCV 3.4 移植到 OpenCV 5**（findContours 返回值、np.int/np.int0 旧别名、
   Tesseract 5 参数、中文路径、headless 弹窗……共 11 处）→ 跑通，但确认它**不适合假山**
3. 改用 **Potrace**（纯 Python）→ **完整还原假山轮廓**（253 曲线 → 101 图元，2 秒）
4. 把两条路线做成**双模式系统**（界面手动选：工程图 / 假山）

**结论**：**"图片转 CAD"没有万能方案**——规则图走多Agent流水线，有机形状走 Potrace 轮廓拟合。
能做出这个判断，本身就是工程能力。

## 7. 预设面试问答

**Q：为什么不让大模型直接看图写代码？**
A：试过（B 臂）。大模型缺精确坐标，几何只能是"大概"，而且结果不稳定。所以正确做法是**算法给精确坐标、大模型负责语义和组装**（D 臂）。

**Q：怎么保证 AI 不胡说？**
A：加**客观校验**——把生成的 DXF 渲染回图片，和原图比 SSIM/IoU/Chamfer。差就打回重做。再用**保最优**保证不劣化。

**Q：为什么要多臂？**
A：对照实验发现，CV 可靠时接地式生成最好，CV 失效（椭圆/剖面线）时纯语义生成更稳。**没有单一路线通吃**，所以跑多条、用客观指标仲裁。

**Q：这个项目的边界在哪？**
A：简单/中等单视图零件图效果好；多视图装配图（real04）还在 0.53，属于研究级难题。我把它定位成**辅助工具**，不是全自动。

**Q：用了什么技术？**
A：Python、OpenCV、RANSAC/Kasa 拟合、ezdxf、LangGraph 多Agent 编排、RapidOCR、通义千问 VLM、DeepSeek、Potrace。

**Q：假山和工程图为什么要分开？**
A：假山是自由曲线，规则几何（直线/圆/弧）抓不住；机械图管线也不行（实测几乎空白）。
所以我按图形类型分了两个模式：工程图走多Agent，假山走 Potrace。**没有万能方案，选对路线才是工程判断。**

**Q：你这工具什么图都能转吗？**
A：不能，我也不吹。简单/中等工程图（方框、圆、槽、孔）和假山效果好；
**复杂多视图装配图只能部分重建**（多臂仲裁后 SSIM ≈ 0.63），因为没把多视图、密集剖面线抓全。
**清楚自己的边界，比说"什么都能"更可信。**

**Q：为什么加入"大模型直接画"这一路？**
A：对比实验发现，纯 CV 在复杂图上会"漏几何"，而强视觉模型（DeepSeek）能"整体理解后一次画全"，
虽然坐标不那么精确，但**更完整、更连贯**。两者互补，所以都作为提案、由客观仲裁择优。
