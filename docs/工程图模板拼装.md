# 工程图：参数化模板拼装与原图校验

工程图默认入口已改为 `core.ensemble.run_ensemble()` → `engineering.pipeline.run_engineering()`。
双击原来的启动文件，选择工程图即可使用。假山入口及共享渲染、导出、预处理模块保持不变。

## 默认流程

1. 原分辨率读取，OCR 去重并保留歧义记录。文字以原生 TEXT 输出，按实际字形范围设置位置、宽度和方向，中文使用黑体字体样式。仅移除文字框内完整的字形连通域，保护穿过文字框的几何线。
2. 用局部像素测量检索参数化模板：矩形、圆、圆弧、椭圆、圆角矩形、长圆槽。模板保证相切、闭合等几何关系。
3. 每个候选检查完整边界的像素支持与拟合误差，拒绝无证据的补全和重复边界。按候选区域关联同心圆与孔阵列，关系记录不强行移动孔位。
4. 未被可靠模板解释的部分保留为可编辑线、弧或多段线，不整块擦除剖面或删除短线。
5. 分别导出连续线条候选 CLEAN、模板组合候选 LIBRARY，重新渲染实际 DXF。交点处合并近切向线条，模板替换保留边界连接点；规则彩色虚线组使用原生 CAD 线型。正常 CAD 线宽不再由图片像素粗细直接换算。
6. 同时记录原生文字数、多段线顶点数、短线段数和几何覆盖指标；模板必须减少几何复杂度。原图相同画布的图像指标仅用于辅助选优，不代表文件合格。所有自动输出保留待核对状态。
7. 从 OCR 与两端界线证据关联尺寸；多标注冲突、OCR 多方向识别冲突或证据不足时保持像素单位。毫米版仅缩放同一份获选 DXF，不重新生成另一套几何。
8. 识别到的数字/文字使用 TEXT；有两端界线、尺寸线与文字位置证据的直线尺寸改为原生 DIMENSION，块内文字为 MTEXT。保留原界线，移除被替换的尺寸线和重复文字。像素版使用原图文字覆盖值，不把该值伪装成像素几何的实际测量值；暂不建立对零件轮廓的关联式约束。
9. 每个候选导出前执行几何复核：密集采样多段线边，验证圆/圆弧拟合误差、转角覆盖和原图边界支持；符合条件才替换为 CIRCLE/ARC，并保留邻接端点。规则多边形、未完成圆弧不能强制补成整圆。
10. 配置了视觉模型时，先用文字裁剪拼图独立转录，字符有实质变化时再用整张原图二次确认；最后比较原图与实际 DXF 渲染并记录疑点。模型不输出执行代码，不凭其建议修改坐标。

## 运行

```powershell
python cli.py ensemble "图片路径.jpg"
python cli.py run "图片路径.jpg" --out out/engineering
python cli.py ensemble "图片路径.jpg" --no-ocr
python cli.py ensemble "图片路径.jpg" --no-ai-review
```

GUI 结果在 `demo_out/engineering/`，命令行 ensemble 默认在 `data/engineering/`。每次运行生成内容摘要＋独立运行 ID 的子目录，避免同名输入覆盖或命中旧缓存。

每个目录包含 `best.dxf`、候选 DXF/PNG/IR JSON、`overlay.png`、`error.png`、`report.json`。叠加图蓝色是原图、红色是输出、黑色是重叠；误差图只显示超出 2 原图像素容差的漏线/多线。像素 DXF 使用无单位设置，缩放版显式使用毫米。

## 模板库和模型提示词

`engineering/primitives.py` 定义模板参数及确定性生成器，`engineering/recognize.py` 用测量拟合检索模板，`engineering/prompts.py` 保存按候选 ID 和视图区分批复核的提示词及响应校验。

这是一套结构化几何库，不需要向量数据库来存每一种矩形大小。模板参数和关系可继续扩展；未知结构始终有保真描线后备路径。

工程图默认在已配置 `DASHSCOPE_API_KEY` 时调用现有视觉模型做文字复核与整图复核。未配置时使用本地 OCR 和几何复核。`--no-ai-review` 或 `ENGINEERING_AI_REVIEW=0` 可关闭云端复核；`--no-ocr` 只关闭 OCR，不等于关闭整图 AI 复核。网络失败保留本地结果并记录原因，不声称模型复核成功。可选命令：

```powershell
python cli.py ensemble "图片路径.jpg" --semantic
python cli.py ensemble "图片路径.jpg" --cloud-proposals
```

`--semantic` 使用现有通义千问配置复核候选语义，仅记录分类、关系与待核验项，不绕过像素验证改坐标。`--cloud-proposals` 额外运行旧生成路线，并在相同画布下仲裁；这些路径会调用原项目配置的云 API。

旧代码生成提示词也已保留多段线、椭圆与短线，取消静默截断和主动省略关键结构。内层轮次选优与外层仲裁使用统一的前景评分。

## 验证

```powershell
python -m pytest tests -q
python -m tools.eval_engineering "1.jpg" "2.jpg" --out out/engineering_review --baseline-dir data/tmp/ensemble
```

测试覆盖独立栅格样本中的四孔和长圆槽、旋转与缩放、圆弧不被补成整圆、正常端点保护、渲染坐标、完整序列化、尺寸冲突、相同几何缩放、模型 ID 校验、显式离线与隔离输出，以及实际 DIMENSION/MTEXT 导出、数字二次确认、AI 失败回退和规则多边形保护。

验收脚本只处理明确传入的图片，不扫描桌面或运行假山；历史 DXF 只读并用新渲染器重评，不能直接比较旧版自动缩放后的 SSIM。

## 边界

- 线条 F1 是指定像素容差下的前景指标，不能称为 CAD 正确率或制造精度。
- 识别且成功分离的文字以 TEXT 或 DIMENSION 块内 MTEXT 输出；尚未识别或有歧义的文字仍可能残留为笔画，不承诺自动识别全部字。已实现的原生标注以直线尺寸为主；半径、直径、角度及不明确的引线仍保留文字与几何，不强行关联错误对象。
- DIMENSION 是真正的 CAD 尺寸实体，但当前图像重建中的标注值是显式覆盖文字，尚不是零件几何改变时自动追踪的关联式标注。像素单位图不具备制造尺寸保证。模型复核也可能出错，尤其是数字、小数点和直径符号；报告仅供辅助核对。
- 复杂剖面线、螺纹、曲线交点和细小闭合轮廓仍需改进；已减少碎线，但不能宣称达到制造图纸质量。原生 CAD 软件中的显示、字体替换与编辑体验仍需实际验收。
- 粗扫描线内部封闭的一像素白缝会被修补，细小真实结构存在歧义时应对照原图检查；不对开放空白间隙执行全局闭合。
- 复杂图仍可能使用较多多段线。模板匹配失败时保留原形，不保证全部语义对象自动恢复。
- 孔阵列与同心关系目前采用测量证据记录，不用模糊的关系猜测强制调整实际坐标。
- 视图区分是候选区域分割，密集相连视图可能仍属于同一区域；跨区域不强行拼接。
- 部分测试图是生成图片，标注、图形比例和多视图可能互相矛盾；这种输入不能自动证明物理尺寸正确。
- 开发验证覆盖独立 Python 3.12 与项目原 Python 3.14 环境，未修改原环境依赖；原 OCR 版本对小字可能给出更低置信度，由视觉复核进一步读取。已验证的核心包版本记录在各次运行报告中。
