## 1. 项目概述

Sketch2CAD 把「黑白线稿 / 图片」自动转换为「可编辑 DXF CAD 图纸」，覆盖**工程图**与**假山（有机形状）**两类场景。

核心思路：**精确的事交给算法，理解的事交给 AI，对错由渲染回图的客观指标裁决。**

定位为**辅助级**矢量化：AI 出 70~80% 初稿，人工精修，把"把图片重画成 CAD"的重复劳动降到最低。**不做**"一键全自动出完美 CAD"。

## 2. 背景与问题

- **人工描图**：把图片转成 CAD 是完全重复劳动，慢、贵、易错。
- **传统光栅转矢量工具**：只会描像素边界，输出成千上万条碎线段，不懂"这是直线 / 圆 / 标注"。
- **纯大模型**：能"看懂图"，但给不出精确坐标，画出来"大概像、尺寸对不上"。
- **业界现状**：尚无"一键全自动出完美 CAD"的方案，因此本项目做"辅助级"落地。

## 3. 目标与非目标

**目标**：图片 → 可编辑 DXF 的自动化输出；用客观指标量化质量；结果可控、可解释、可回退（"保最优"，输出永不劣于基线）。

**非目标**：不追求全自动完美重建；不做 3D；不面向照片级彩色图纸（聚焦黑白线稿）。

## 4. 目标用户

- 制图 / 工程技术人员：把纸质图、截图、扫描件数字化为可编辑 CAD。
- 园林景观设计师：把假山、置石线稿转为 CAD 轮廓。

## 5. 范围

- ✅ 支持：简单 / 中等工程图（方块、圆、槽、孔、圆弧、椭圆、尺寸标注）；假山等有机曲线。
- ⚠️ 受限：复杂多视图装配图（图框 + 标题栏 + 剖面线 + 透视角）仅能"部分重建"，需人工核对。
- 说明：图像相似度**不代表** CAD 合格；输出为**像素坐标系**（`$INSUNITS=0`，不假装是 mm）。

## 6. 功能需求（FR）

### 6.1 双模式
- **FR1 模式选择**：用户手动选「工程图」或「假山」，避免自动误判。

### 6.2 工程图管线（v10）
| 编号 | 阶段 | 说明 |
|---|---|---|
| FR2 | 识别文字与数字 | OCR 识别标注；OCR 失败**不破坏线条几何**（鲁棒降级） |
| FR3 | AI 复核文字 / 数字 | 视觉模型纠错与补充；不确定项标注待人工确认 |
| FR4 | 提取线条 / 圆孔 / 零件轮廓 | 生成 **CLEAN（连续线条）** 与 **LIBRARY（模板拼装）** 两类方案 |
| FR5 | 杂线清理 + 虚线对齐 | 去除扫描杂线；测量虚线节距并对齐轴线 |
| FR6 | 尺寸关联 | 把尺寸数字绑定到对应尺寸线 |
| FR7 | 生成 CAD | DXF 原生 TEXT + 尺寸标注（DIMENSION）+ 引线（LEADER） |
| FR8 | 方案择优 | `cad_score` 综合分择优（含结构惩罚项） |
| FR9 | 局部补漏修复 | 检查遗漏文字 / 标注并补回 |
| FR10 | 剖面填充 | 仅在**选定方案**上最后生成 native hatches |
| FR11 | 最终图像复核 | 视觉模型整图复核，输出需人工确认清单 |
| FR12 | 比例校准 | 由标注反推 mm/px，输出**真实尺寸** DXF |
| FR13 | 交付 | 单文件交付（DXF + 预览图 + 指标报告） |

### 6.3 假山通道
- **FR14 中心线提取**：骨架化 + 追踪 → 图元拟合（直线 / 圆弧 / 圆）→ DXF；**纯本地离线**，约 2 秒。

### 6.4 通用
- **FR15 客观仲裁**：把候选方案渲染回图与原图比对，取最优并保留历史最优（"保最优"）。
- **FR16 图形界面**：选择图片、选择模式、一键处理、**进度显示**、自动打开结果。

## 7. 非功能需求（NFR）

- **性能**：假山约 2 秒（纯本地）；工程图约 1~2 分钟（含云端 API）。
- **可靠性**：单臂 / 单方案失败自动跳过；结果缓存；保最优回退。
- **可解释**：全流程**坐标契约** + 质量指标（geometry recall / SSIM / Dice）+ 报告。
- **可维护**：引擎与场景解耦；工程图管线分阶段可测。
- **成本**：使用视觉模型（可配 DeepSeek / 通义千问）；token 用量可控，可 `--no-ai-review` 关闭。

## 8. 系统架构

```
输入（黑白线稿/图片）
   ├─ 工程图：OCR+AI复核 → 提线条/圆孔/轮廓(CLEAN·LIBRARY) → 杂线清理+虚线对齐
   │            → 尺寸关联 → 生成CAD(原生尺寸/引线) → 方案择优 → 局部修复
   │            → 剖面填充 → 最终AI复核 → 比例校准 → 单文件交付
   └─ 假山：中心线提取(骨架化+追踪)+图元拟合 → DXF（纯本地离线）
```

## 9. 技术栈

- 语言 / 图像：Python、OpenCV、scikit-image、NumPy、SciPy
- 矢量化：HoughLinesP、HoughCircles（+覆盖度验证）、Kasa 圆/弧拟合、椭圆拟合、图元装配
- CAD：ezdxf（生成 DXF）、matplotlib（DXF 渲染回图）
- OCR：RapidOCR（本地、支持旋转文字）
- 大模型：视觉模型（理解 / 复核 / 生成）、DeepSeek（决策）
- 界面：tkinter

## 10. 评测指标与结果

- 图像级：SSIM、Dice、Chamfer、IoU；结构级：图元数量 / 类型、短线段比例。
- 简单 / 中等工程图：SSIM 0.75~0.84；复杂装配图：较基线 0.38 → 0.63。
- 比例尺校准：real01 标注 60×50，还原包围盒约 61.5×50.0 mm，误差 <3%。

## 11. 里程碑

1. 合成数据生成器 + 评测脚本（IoU/SSIM/Chamfer）
2. OpenCV 确定性矢量化基线
3. 接入 OCR + VLM 语义理解
4. 多 Agent 协同 + 校验回环
5. 算法增强（图框/剖面线/尺寸线剔除、圆验证、椭圆、图元装配）
6. 多臂对照实验 + 集成仲裁
7. 双模式 + GUI + 比例尺校准
8. **工程图 v10**：OCR+AI 复核、杂线清理 + 虚线对齐、原生尺寸/引线、剖面填充、局部修复、进度显示、单文件交付

## 12. 风险与限制

- 复杂多视图图的瓶颈是"检测不全"，只能规整"已抓到的"。
- 依赖云端 API：有成本与延迟、结果有随机性（由"保最优"兜底）。
- 输出仍需人工核对；图像相似度不代表 CAD 合格。
- 假山通道已申请国家发明专利（申请中）。
