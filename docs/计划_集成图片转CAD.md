## 1. 现有工具评估（D 盘那两个）——已查清

位置：`D:\资料\666...\图片转CAD\`
- **第一款**：`img2cad.exe` → 查 exe 元数据 = **商业软件 Img2CAD**（img2cad.com，2018，v7.6）
- **第二款**：`R2V32` → 老牌**商业软件 R2V**（Able Software）

**那个包里"开源"的部分是什么？**
`D:\资料\doc\` 里是 **Tesseract OCR** 的 `AUTHORS / LICENSE / README.md`（Apache-2.0）。
→ 也就是说，卖家打包的**开源项目是 Tesseract（文字识别）**，它**不做"图片转矢量"**。
另外包里还有 **Inkscape 安装包**，Inkscape 的"位图转路径"用的正是开源的 **Potrace**。

**结论**：
- 包里的开源 = Tesseract（OCR）→ 我们已有 RapidOCR，不需要它
- 真正的"图片转CAD"（Img2CAD / R2V）= 商业闭源 → 不嵌入
- 想做"不规则形状矢量化"，正确开源路线 = **Potrace / Autotrace**

### ⭐ 找到卖家用的那个开源项目了：Image2CAD

**`https://github.com/adityaintwala/Image2CAD`**（Apache-2.0，185 stars，2019 论文）
- 做的正是「光栅 CAD 图 → 可编辑 DXF」
- 依赖：**OpenCV 3.4.2 + Tesseract OCR + ezdxf + numpy + scipy**（正好解释了包里那套 Tesseract/leptonica/cairo DLL）
- 管线：**箭头检测 → 尺寸线检测 → 尺寸文字(Tesseract) → 直线检测 → 圆检测 → 关联 → DXF**（论文称自动模式 90% 成功率）
- 作者自述：开源版是论文原版的"精简版"，**泛化性/鲁棒性不如原版**

**定位**：它是一条**经典的传统 IP 管线**（无大模型、无校验回环、无清洗）。
比我们的项目更"传统"，但可作为**对照基线（G 臂）**，也能借鉴它两点：
① 箭头检测（我们还没有）② 尺寸与几何的关联（我们靠 OCR 邻域粗略剔除）

**风险**：为 OpenCV 3.4.2 写的，跑在 OpenCV 5.0 上可能要修不少 API（`findContours` 返回值等都变过），是个潜在的坑。

## 2. 三条路线对比

| 路线 | 做法 | 评价 |
|---|---|---|
| **A 黑盒调用** | `subprocess` 调购买的 exe | ❌ 闭源、GUI 难自动化、许可证风险、不可改进 |
| **B 开源自建**（推荐） | 用 Potrace/Vtracer 自建"不规则轮廓通道"，接入集成流水线 | ✅ 开源、可控、能自动化、能改进、能写进专利 |
| **C 拉 GitHub 仓库改造** | `git clone` 某矢量化仓库再改 | 与 B 等价，直接 `pip install` 更省事（B 优先） |

**推荐：B**。开源候选实测结果：

| 库 | 安装 | 可用性 |
|---|---|---|
| **`potracer`**（PyPI，import 名是 `potrace`） | ✅ 已装 | ✅ **实测可用**：real01 提取 14 条曲线、84 段（位图→平滑贝塞尔曲线） |
| `vtracer`（Rust 绑定） | ✅ 导入 OK | ❌ **一转换就段错误崩溃**（Python 3.14 ABI 问题） |
| `pypotrace`（C 绑定） | 需编译 | 不推荐 |

**结论：用 `potrace`（纯 Python Potrace）做"不规则轮廓通道"。**（即卖家包里 Inkscape 用的那个引擎）

## 3. 推荐方案设计

在现有集成流水线上，新增一条通道：

```
输入线稿图
 ├─ 规则几何通道：OpenCV/RANSAC → 直线·圆·圆弧        （已有）
 ├─ 语义/代码通道：B / D 提案                          （已有）
 └─ 【新增】不规则轮廓通道 F：
       轮廓分割（区分"有机形状"vs"机械图元"）
         → potracer/vtracer 拟合成平滑多段线/样条
         → 写入 DXF（layer=organic）
              ↓
     集成仲裁（已有）：所有提案渲染回图比对，取 SSIM 最优
```

**关键点**：
1. 复用现有的**客观仲裁**——不规则通道作为第 4 个提案，谁分高用谁
2. **模式路由**：规则图（零件图）走 A/D；有机图（假山、植物、地形）走 F
3. 输出统一进 DXF，可分层（geometry / organic / text）

## 6. 风险

- `vtracer` 是 Rust 绑定，Python 3.14 轮子可能没出 → 先用纯 Python 的 `potracer` 兜底
- 不规则通道和规则通道的**区域分割**是难点（一张图里两者混在一起）
- 不要为了"接工具"而接工具——**只有当图里真有有机形状时才需要它**（否则 A/D 已够）

## 8. 落地结果（已完成 ✅）

1. **Image2CAD 已移植并跑通**：从 OpenCV 3.4 → OpenCV 5（11 处改动，见 `third_party/Image2CAD/PATCHES.md`）。
2. **但它不适合假山**：同一张假山线稿上，Image2CAD 几乎提取不出东西。
3. **改用 Potrace**：完整还原轮廓（253 曲线 → 101 图元，2 秒），落地为 `core/rockery.py`
   （Potrace → IR 多段线 → DXF）。
4. **双模式系统落地**：`gui.py`（tkinter）——上传图片 + 选模式（工程图 / 假山）→ 出 DXF。
   双击 `启动.bat` 运行。

**最终结论**：`图片转CAD` 没有万能方案。工程图 → 多Agent集成；假山/有机形状 → Potrace。
