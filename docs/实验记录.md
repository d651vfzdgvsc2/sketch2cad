# 对照实验记录

> 记录 A/B/C/D/E 五臂对照实验的设计、数据与结论。
> 复现：`python -m experiments.run_compare --arms A,B,C,D,E`

---

## 1. 实验目的

回答一个问题：**"图片 → CAD"，到底哪种技术路线最好？**
- 纯算法（CV）？
- 纯大模型（VLM 写代码）？
- 还是算法 + 大模型融合？

不靠感觉，用**同一批图 + 同一套客观指标**做对照。

---

## 2. 五臂定义

| 臂 | 名称 | 输入给大模型 | 说明 |
|---|---|---|---|
| **A** | 确定性 CV 矢量化 | —（无大模型生成） | OpenCV/RANSAC 提直线·圆·弧 + LLM 决策回环 |
| **B** | 纯语义代码生成 | VLM 的文字描述 | 图 → VLM 文字 → LLM 写 ezdxf 脚本 |
| **C** | 朴素接地生成 | CV 坐标 + OCR（全量、不筛选） | 把上百个图元全给 LLM，让它照画 |
| **D** | 融合（克制接地） | CV 精确坐标 + OCR + VLM 描述 + "只画几何"约束 | 本次实验的核心产物 |
| **D** | 融合（克制接地） | CV 精确坐标 + OCR + VLM 描述 + "只画几何"约束 | 本次实验的核心产物 |
| **DS** | 大模型直接画 | **只看图**（DeepSeek `deepseek-chat`） | 强视觉模型直接写 ezdxf 脚本 + 错误反馈重试 |
| **E** | 集成仲裁 | 全部提案（A/B/C/D/DS） | 全部渲染回图，取 SSIM 最优（保最优） |

**指标**：把每个臂产出的 DXF 渲染回图片，与原图比 SSIM / IoU / Dice / Chamfer。

---

## 3. 数据集

- **合成集**：`datagen` 用 ezdxf 画图形 → 导出 DXF（标准答案）→ 渲染成线稿 + 加噪声、加粗。要多少有多少。
- **真实集**：豆包生成的黑白工程图 4 张（`data/real/`），复杂度递增：

| 文件 | 内容 | 难度 |
|---|---|---|
| real01 | 方形 + 内切圆 + 尺寸标注 | 简单 |
| real02 | 三视图零件板（圆角、腰形槽、孔） | 中等 |
| real03 | 轴类零件剖视图（椭圆端面、螺纹、键槽、剖面线） | 较难 |
| real04 | 装配图（4 视图 + 图框 + 标题栏 + 剖面线） | 难 |

---

## 5. 结论

1. **没有单臂通吃**：
   - D（接地式）在 CV 可靠时最优（real01/03）
   - B（纯语义）在 CV 失效（real03 的螺纹/椭圆）时更稳
2. **因此必须集成 + 客观仲裁**：跑多条路线，用渲染回图指标选最优。
3. **保最优是刚需**：大模型有随机性，没有保最优就可能越调越差。
4. **算法增强收益巨大**：圆周覆盖度圆验证（real04 假圆 54→7）、尺寸线剔除（real03 实体 118→68）等，把确定性通道 real04 从 0.38 拉到 0.53。
5. **强视觉模型是有效补充**：DeepSeek 直接画（DS 臂）能补 CV 的"漏几何"，与 CV 互补；加入后平均最佳 0.729 → 0.756。
6. **提示词工程很关键**：给模型正确的 ezdxf API 清单 + 错误反馈重试，脚本成功率与效果显著提升。

## 6. 调试过程中踩的坑（工程能力体现）

| 现象 | 根因 | 解法 |
|---|---|---|
| 迭代 4 轮，最优却没生效 | LangGraph 的 `AgentState` 没声明 `best_*` 字段，被静默丢弃 | 把字段补进 State schema |
| 代码生成臂全部判失败 | 执行器检查的是随机路径，脚本却存到了指定路径 | 统一输出路径 |
| 大模型返回空/乱 | 误以为 DeepSeek 有视觉；实测其明确回复 "image is unsupported" | 换用通义千问 VLM |
| 所有 API 请求报 ProxyError | 系统设了本地代理 127.0.0.1:7897 但代理没开 | `requests.Session.trust_env=False` 直连 |
| 渲染全失败、PNG 不生成 | OpenCV 在 Windows 不支持中文路径 | `imdecode/imencode + tofile` 兼容层 |
| 圆被画成虚线、碎线一堆 | 半径上限设小了，遮罩没盖住真实圆 | 自动半径 + 弧线过滤 + 覆盖度验证 |
| 竖排尺寸文字丢失 | 默认 OCR 不认旋转文字 | 0°/90°/270° 多方向识别 + 去重 |
